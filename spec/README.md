# GPU Sentry

## 需求介绍

在进行深度学习任务时，复杂的代码经常错误频出，而一个 critical error 就会导致程序的崩溃。

- 企业级的日志分析工具昂贵且复杂，对于个人开发者或者小型研究团队难以实现。
- 终端重复输入 `nvidia-smi` 的土办法低效且无趣。

因此需要针对科研人士开发一款**命令行可用的 GPU 监测报警系统**，让开发者能够在第一时间收集到 GPU 的使用情况，提高科研人员的开发效率。

### 功能具体介绍

- 监控日志面板 (已经有成熟的产品 nvitop，故本产品不再重复造轮子)
- 自动监听并且 24h 收集显卡使用数据，写入数据库中（本地持久化存储）
- 链接飞书 Webhook 实现信息的及时同步
- 根据写入的数据对每天 & 每周 & 每个月的使用情况做具体分析，实现周期性汇报（链接飞书 Webhook）
- 短期实时汇报，例如如果出现了使用量突然减少的情况，可以做汇报
  - 更多的功能，可以设计自定义规则在什么时候做汇报

## 接口设计

可以使用命令行接口 `gpusentry` 一键调用

### 监控日志面板

默认参数，可以通过 `gpusentry` 或者 `gpusentry board` 调用，如果调用直接使用在终端启用 nvitop 命令

其余功能主要在后端自动完成：

可在 tmux 终端中运行 `gpusentry backend` 即实现后端的持久监控运行

- 自动监听采集 gpu 数据（cpu 内存 硬盘 显存 gpu 使用量等），存储到本地数据库
  - 设定间隔为 5s
- 定时每天 23:00 & 每周日 23:30 & 每月最后一天的 23:45
  - 分析具体的使用情况
  - 画图表 & 做使用量分析
    - 这一部分接入 LLM 智能助手
  - 定时发送到飞书 Webhook
- 如果触发预警规则，则利用 飞书 Webhook 发送消息
  - 默认规则 1：
    - 如果连续 5 分钟 GPU 的显存占用超过 2000 MB，则代表显卡正在工作
    - 如果连续 5 分钟 GPU 的显存占用低于 100MB，则代表显卡停止工作
    - 任何从**工作状态**到**停止工作** 状态的转变均需要汇报
  - 默认规则 2：
    - 监控使用 GPU 超过 100 MB 的线程
    - 如果线程退出了，汇报
